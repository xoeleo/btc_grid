# 普通网格清仓与恢复安全边界

本次修改仅针对普通 Grid 的真实交易控制及共用 Bybit 查询网关；不部署、不触发交易。Rebalance 的账本和运行控制不作为本次实盘验收范围。

## 持仓归属

现货“清仓并停止”只针对已建立可信基线的策略净持仓。数量为策略正净持仓与当前交易钱包余额的较小者，再按交易所 qtyStep 向下取整。执行器再次校验账本和钱包；余额变化时拒绝本次提交，不用小数位代替交易所步长。交易所仍可能因冻结余额或单笔数量限制拒单，这不能显示为清仓完成。

新建策略不再自动将钱包原有资产记入策略。停止后的重试与补录不能绕过策略账本，不能根据钱包余额补造买卖成交。全钱包清仓不属于该接口。

## 停止与恢复

停止请求、撤单待确认标记、清仓 clientOrderId、已入账执行数量和恢复水位保存到状态文件。每次交易所请求前先持久化本地未知状态；文件使用同目录临时文件、force 和原子替换，失败不删除上一份状态。

撤单 HTTP 成功只是接受请求。订单只有通过私有流或 REST 确认终态，且累计成交数量已恢复入账，才允许进入清仓。撤单失败、查询缺页、提交响应丢失、部分成交、余额不足、粉尘或任何未解释的差异，都保留监控并禁止新的策略订单。

清仓单号在提交前持久化。重启与重试只查询同一单号，不因超时重复提交；部分终态或明确拒单也不会自动生成第二单，需要人工核对剩余策略持仓。只有已确认完整成交且策略净持仓为零才报告完成。30 秒等待只是操作等待期限，超时不代表撤单或清仓成功，也不关闭监控。网络调用期间采用同一状态锁，回调可能延迟；不会据此推断成功。

## 查询完整性与旧状态

开放订单、订单历史与执行历史按游标翻页，接口错误、异常响应、重复游标或缺少关键成交字段直接失败。执行恢复查询整个交易对的明确时间窗口；忽略其他业务订单，发现本地没有记录的 GRID_/MANUAL_FLATTEN_ 成交时阻止交易并要求核对。执行 ID 用于去重，订单累计成交量用于检查是否缺少成交。

当前适配器保守地只支持最近 7 天的执行恢复区间，并明确拒绝更早的请求；这不是对 Bybit 所有账户历史保留能力的声明。每轮成功恢复推进持久化水位，并保留一秒重叠。长时间停机或持续查询失败超过支持窗口时，不截断历史来继续下单，必须先做完整的离线恢复。

**旧版非空账本、缺失恢复水位、钱包自动接管产生的历史状态，以及未知归属订单，不会自动升级为可信状态。** 程序保留查询和告警，禁止下单及自动清仓。需要人工核对策略成交、手续费、订单终态、账本及恢复起点后，由单独审核的迁移流程建立基线；本次不提供直接将不可信账本标为可信的按钮。请保留原状态、SQLite 与日志，不要删除状态以绕过保护。

本地离线测试只能证明模拟情境中的状态转换；仍需在隔离账户/测试网验证交易所真实成交、断流、重启和余额可卖限制后，才能判断实盘上线条件。
