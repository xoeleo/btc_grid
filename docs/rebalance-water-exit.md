# 再平衡动态水位自动退出

1% 减半、2% 清仓均使用本 Cycle 的动态保本水位计算收益幅度，并叠加相对开单价
的方向条件。开单价使用当前 Cycle 首笔成交价 `CurrentCycleSummary.startPrice`；
开单方向使用首笔成交确定的 `entryDirection`，不随后续补仓、减仓或动态水位改变。
当前价格沿用现有行情口径：优先标记价格，无有效标记价格时使用最新成交价格。

| 规则 | 原条件 | 叠加后条件 |
| --- | --- | --- |
| 做多 1% 减半 | 动态水位收益幅度 ≥ 1%，本波段未减半 | 原条件，且当前价严格高于开单价 |
| 做多 2% 清仓 | 动态水位收益幅度 ≥ 2% | 原条件，且当前价严格高于开单价 |
| 做空 1% 减半 | 动态水位收益幅度 ≥ 1%，本波段未减半 | 原条件，且当前价严格低于开单价 |
| 做空 2% 清仓 | 动态水位收益幅度 ≥ 2% | 原条件，且当前价严格低于开单价 |

当前价等于开单价时不触发。开单价格缺失、非正数或开单方向未知时，也不触发新的
自动减半或清仓。达到 2% 时仍优先清仓，可以直接跳过减半。

例如多单开单价 100000，动态水位经交易后降至 98000，即使当前价 99960 已达到
动态水位 2%，仍等待当前价高于 100000 后才触发清仓。

本次只叠加自动触发条件。原有的盈利暂停网格、回到亏损侧恢复网格、再次盈利波段
可减半、持久化恢复、订单与成交核对流程继续保留。已触发的退出沿用原流程：
减半仍可因回到动态水位亏损侧而撤单恢复，已锁定的全平继续执行到成交确认。
手动减仓、手动平仓及达到目标资产比例后保留仓位的结束规则继续按各自条件执行。

## 手动加仓 10%

再平衡页面的“手动加仓 10%”按点击时当前 Cycle 的累计净持仓绝对值计算，数量按交易所步长
向下取整；多仓买入、空仓卖出。例如净多仓 0.282 BTC，步长 0.001 BTC，加仓量为 0.028 BTC。
操作需要监控运行、Cycle 未结束且持仓方向明确；行情缺失或过期、其他仓位调整尚未完成、
平仓指令已锁定、低于最小数量/名义金额或超过最大持仓上限时拒绝加仓。

请求先持久化锁定数量和方向，再撤销当前 Cycle 的再平衡挂单，并完整核对撤单期间的成交。
以核对后的净持仓为基准加上锁定数量，按对手盘口限价下单；每笔不超过配置的单笔上限，
必要时分笔执行。部分成交、改价和重启均继续同一目标；订单结果未知时等待核对，禁止重复下单。
若撤单期间持仓归零或方向改变，则停止加仓并等待处理。达到原有目标资产比例或手动平仓时，
原有结束/平仓规则仍优先执行。

接口为受保护的 `POST /api/rebalance-add-cycle`。请求成功仅表示已受理，成交以实际成交账本为准。
加仓确认成交后继续当前 Cycle，按原动态水位规则决定盈利暂停、恢复网格、减半或清仓。

## 手动加减仓不作为网格上一笔成交

手动加仓、手动减仓正常计入 Cycle 的净数量、成本、手续费和盈亏；不会更新网格参考价、
前一笔参考价、参考方向或连续买卖成交计数。下一次网格挂单继续以上一笔非手动成交计算。
自动水位减半、自动清仓的原有规则保持不变。

| 路径 | 修复前 | 修复后 |
| --- | --- | --- |
| 运行中收到手动成交 | 同时更新持仓与网格价格历史 | 更新持仓和成本，保留网格价格历史 |
| 重启恢复 | 取最后一笔买卖成交作参考 | 跳过已标记的手动成交，持仓与成本仍取完整账本 |
| 再平衡成交列表“较上笔” | 手动成交进入价格差链，分页可能丢失前值 | 跳过手动成交，使用跨页、筛选前的服务端参考价 |
| 挂单价差与情景估算 | 使用最后一笔实际成交价 | 使用运行中提供的 `gridReferencePrice` |

新的手动订单使用 `RBAL_MANUAL_` 前缀，成交元数据保存 `manualPositionAdjustment=true`。
兼容旧版未完成的手动订单时，由持久化手动控制状态识别；历史订单则依据手动请求、成交及
退出手动阶段的日志核对后补元数据。不会将全部 `RBAL_WATER_` 订单当作手动订单。
