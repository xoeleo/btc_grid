# 已结束 Rebalance Cycle 的手动续跑

本功能经模拟网关回归和构建验证。提交、部署及实盘恢复是独立步骤；部署不会自动调用实盘续跑接口。

历史 Cycle 表中，最近一笔因目标资产比例达到而结束且保留仓位的记录显示“继续运行”。先读取预览，确认结束参考价、当前价、价差和允许区间，再提交续跑。区间外不会恢复或提交委托；不自动等待价格回归后启动。

旧记录没有保存区间、网格参数快照时，预览明确显示使用当前已保存的波段区间和网格参数。区间文件必须真实存在，不能用默认区间代替。新的结束记录保存区间和参数快照；后续参数变化需要重新核对。预览确认值绑定 Cycle、区间及网格参数，配置变化后旧确认失效。

## 执行与账本

- 允许选择历史中尚未续跑、且保留仓位的 Cycle；同一 Cycle 必须选择它最近一次结束记录。平仓结束、已经产生新交易、已有活动 Cycle 或委托、实际仓位方向不符或数量不足、行情/账户过期、私有流不健康等情况均拒绝。
- `GET /api/rebalance-continue-cycle?executionId=...` 只预览；`POST` 提交 `executionId` 和预览返回的 `confirmation`。接口沿用原控制台鉴权，前端不自动重发 POST。
- SQLite 使用 `cycle_continuations` 审计表，以原结束 execution ID 唯一约束实现防重复。原结束标记和所有真实成交保留；已续跑的结束标记不再划断当前 Cycle 或重复计入结束汇总，原结束明细仍可按 ID 查询。
- 恢复原始开始时间、净仓位、成本及交易参考序列，以结束价作为首轮参考，复用 `GridOrderPlanner` 根据当前价格与参考价的距离计算限价和数量，不发送新的初始建仓市价单。
- 在恢复挂单前核对保留仓位和暂停期间资金费。账户原有底仓与本 Cycle 的净成交仓位分开：交易所总仓位可以更大，底仓不补记为 Cycle 成交、成本或收益；只要求实际方向一致、数量足以覆盖本 Cycle。核对未完成时，持久化 `ready=false`，包括进程重启后仍不允许新增挂单；延迟成交可以入账但不触发后续订单。
- 目标资产比例必须先回到未达标侧，才能再次因达标结束，避免恢复瞬间立即结束；此状态持久化。原动态水位完成状态按相同 Cycle 释放，水位和风险规则继续生效。
- 续跑后价格越出已确认区间时请求撤单、暂停新挂单。取消仍以交易所最终回报为准。历史收益和手续费连续累计，原开始时间不重置，暂停时长包含在整个 Cycle 时长内。

## 验证与发布边界

模拟交易网关覆盖价差恢复、无重复初始订单、重复点击、旧结束/错误参考价、新交易、区间外、仓位变化、过期行情/账户、资金费失败/重启恢复、原目标再生效及动态水位完成状态释放。界面脚本独立检查语法，并验证取消确认、区间拒绝、确认参数、双击、超时不重发和按钮可见性。

证据和构建记录在 `.build/cycle-continuation-20261113/`。线上真实私有流、仓位、订单与该 Cycle 的恢复尚未验收。

发布前需要核对当前线上版本并备份 JAR、配置/状态和一致性 SQLite；不得覆盖增长中的生产账本。**使用过续跑功能后，不能直接回滚到不识别 `cycle_continuations` 的旧代码**，否则旧版本会错误划分 Cycle 或重复汇总。应保留账本并使用兼容续跑表的修复版本。

## 完整运行版本发布

本次按用户要求整体构建并发布 Rebalance 应用及全部项目运行依赖，不采用历史版本的方法替换包。普通 Grid 服务、配置和进程不随本次更新。恢复按钮仍由用户手动点击；部署过程不会调用续跑 POST。

## 空闲私有流心跳

私有流的 `pong` 与 `ping` 回复均更新连接消息时间；心跳只证明传输仍活跃，不代替鉴权和订阅确认，也不生成成交。续跑预览与提交使用同一就绪检查：监控运行、订单和资金费查询入口存在、已订阅且最近 60 秒内收到消息。无成交但持续收到心跳时可以通过；断连、缺少订阅或心跳过期时仍拒绝。上线验收应在订阅超过 60 秒后再次执行 GET 预览，不能仅在刚重启后验收。

## 超时重挂

15 分钟与缩距系数沿用保存的网格配置。超时先将本次缩距间距、Cycle、最近成交 ID、参数及原委托 ID 原子写入 `rebalance-state.json.requote.json`，然后只发送撤单。所有旧单确认撤销后，按最新行情、库存和舍入余量重新生成订单，使用已保存的间距；下一轮继续在此间距上缩小，基础网格间距为下限。计划在撤单等待期间重启后仍可恢复，恢复已有委托保留原创建时间与间距。

撤单期间有新成交时，旧计划失效，按最新成交恢复普通网格；重复成交不清除有效计划。已恢复的新委托与旧计划区分，避免重启后误撤新单。发布不主动触发撤单或重挂，以自然超时事件验证线上效果。

## 成交后的即时补挂与拆分成交

已跟踪的委托收到新的终态证据时，在同一调度线程上合并唤醒补挂任务，不等待 15 秒轮询。先完整查询该时间段的成交，核对回报中的累计成交量；如果成交记录暂未可见、还有撤单待确认、或者交易所仍有本地已标为终态的残余委托，则暂缓。短暂不可见最多快速重试三次，原轮询继续兜底。未知委托、其他交易对和重复终态回报不触发交易。即时任务仍走现有账户、行情、比例、区间与退出检查。

Rebalance 网格参考按委托推进。同一订单的拆分成交分别计入数量、成本、费用和盈亏，但保留前一订单的参考价和连续成交步数。重启恢复时合并相邻同委托成交来还原这些参考状态，不改动历史成交记录。普通 Grid 服务不随本次更新。

## 指定历史 Cycle 续跑

历史表中可续跑的保留仓位记录显示“继续运行”。弹窗标明所选结束时间、原开始时间、保留数量、结束参考价、实时价格与价差、保存的区间及只读计算的首轮预计委托。区间外、运行中、行情或连接未就绪、参数不一致、交易所已有挂单等情况，禁用确认并显示原因；关闭、取消和预览不发送 POST。确认可能立即成交，实际按确认时行情复核。当前卡片显示历史续跑来源。

`cycle_fill_owners` 按原初始成交 ID 显式标记所选 Cycle 的成交、资金费和结束检查点；`active_cycle_owners` 保存当前归属。登记与尾部检查在同一写事务中完成，后续新成交和结束标记在保存事务中继承归属，结束后解除活动归属。每个 Cycle 独立计算累计数量、价值、费用、明细分页及统计；暂停期间其他 Cycle 的成交不合并，历史真实成交行不删除或补造。重启恢复继续使用显式归属。回放其他 Cycle 已有成交 ID 时不再次应用到当前仓位。

预览确认值同时绑定账本版本，期间出现新记录需重新确认。归属表仍为空时可以回滚到前一版本；一旦使用指定历史续跑，旧版不认识显式归属，不能再回滚旧版，也不能用备份覆盖增长中的生产账本。
