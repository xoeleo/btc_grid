# 已结束 Rebalance Cycle 的手动续跑

本功能经模拟网关回归和构建验证。提交、部署及实盘恢复是独立步骤；部署不会自动调用实盘续跑接口。

历史 Cycle 表中，最近一笔因目标资产比例达到而结束且保留仓位的记录显示“继续运行”。先读取预览，确认结束参考价、当前价、价差和允许区间，再提交续跑。区间外不会恢复或提交委托；不自动等待价格回归后启动。

旧记录没有保存区间、网格参数快照时，预览明确显示使用当前已保存的波段区间和网格参数。区间文件必须真实存在，不能用默认区间代替。新的结束记录保存区间和参数快照；后续参数变化需要重新核对。预览确认值绑定 Cycle、区间及网格参数，配置变化后旧确认失效。

## 执行与账本

- 仅允许最近一笔尚未续跑的保留仓位 Cycle。平仓结束、已经产生新交易、已有活动 Cycle 或委托、实际仓位不一致、行情/账户过期、私有流不健康等情况均拒绝。
- `GET /api/rebalance-continue-cycle?executionId=...` 只预览；`POST` 提交 `executionId` 和预览返回的 `confirmation`。接口沿用原控制台鉴权，前端不自动重发 POST。
- SQLite 新增 `cycle_continuations` 审计表，以原结束 execution ID 唯一约束实现防重复。原结束标记和所有真实成交保留；已续跑的结束标记不再划断当前 Cycle 或重复计入结束汇总，原结束明细仍可按 ID 查询。
- 恢复原始开始时间、净仓位、成本及交易参考序列，以结束价作为首轮参考，复用 `GridOrderPlanner` 根据当前价格与参考价的距离计算限价和数量，不发送新的初始建仓市价单。
- 在恢复挂单前核对保留仓位和暂停期间资金费。核对未完成时，持久化 `ready=false`，包括进程重启后仍不允许新增挂单；延迟成交可以入账但不触发后续订单。
- 目标资产比例必须先回到未达标侧，才能再次因达标结束，避免恢复瞬间立即结束；此状态持久化。原动态水位完成状态按相同 Cycle 释放，水位和风险规则继续生效。
- 续跑后价格越出已确认区间时请求撤单、暂停新挂单。取消仍以交易所最终回报为准。历史收益和手续费连续累计，原开始时间不重置，暂停时长包含在整个 Cycle 时长内。

## 验证与发布边界

模拟交易网关覆盖价差恢复、无重复初始订单、重复点击、旧结束/错误参考价、新交易、区间外、仓位变化、过期行情/账户、资金费失败/重启恢复、原目标再生效及动态水位完成状态释放。界面脚本独立检查语法，并验证取消确认、区间拒绝、确认参数、双击、超时不重发和按钮可见性。

证据和构建记录在 `.build/cycle-continuation-20261113/`。线上真实私有流、仓位、订单与该 Cycle 的恢复尚未验收。

发布前需要核对当前线上版本并备份 JAR、配置/状态和一致性 SQLite；不得覆盖增长中的生产账本。**使用过续跑功能后，不能直接回滚到不识别 `cycle_continuations` 的旧代码**，否则旧版本会错误划分 Cycle 或重复汇总。应保留账本并使用兼容续跑表的修复版本。
